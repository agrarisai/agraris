Build your first agent on Robinhood Chain

From a small idea to a listing on Agraris, in five steps.

On Agraris, an agent is a program that does a job for someone: it watches, reads, sums up or acts, often with help from an AI model. Agraris lists agents and tools so people can find them. It does not run them for you.

Listing is free. You don't need an account or a wallet. You need a public code repository and a few minutes for the form.

  1. Pick a small idea
  2. Set up a public repo
  3. Add a demo link (optional)
  4. Publish on Agraris
  5. After your listing appears

Step 1. Pick a small idea

Start with one task. Make it work end to end. Add more later.

Some ideas to get you thinking:

  • A simple alert. Watch one address and send you a message when it has a new transaction.
  • A data summary. Once a day, write a short, plain-language summary of activity for one contract.
  • A transaction explainer. Paste a transaction hash, get a few sentences on what happened.

Write your idea down in one sentence. If you need "and" twice, it's probably two agents.

Connecting to Robinhood Chain: see the official Robinhood Chain docs for network settings and RPC. The docs also cover adding the network to a wallet, gas and fees and deploying smart contracts. Everything else is on the docs home page. Robinhood Chain's chain ID is 4663, and Agraris links contract addresses to the explorer at robinhoodchain.blockscout.com.

Step 2. Set up a public repo

People decide whether to try your agent by reading its repo. Keep it public and keep it simple. A layout like this is enough: 

my-first-agent/
├── README.md     what it does and how to run it
├── LICENSE       the terms people can use it under
├── .gitignore    keeps keys and local files out of git
└── src/          your agent's code

Never commit private keys, API keys or passwords. Put them in a local file that .gitignore excludes, and explain in the README which ones are needed.

Push it to GitHub (replace you with your username):

git init
git add README.md LICENSE .gitignore src
git commit -m "First version"
git branch -M main
git remote add origin https://github.com/you/my-first-agent.git
git push -u origin main

Your README should answer four questions. Copy this checklist into it and fill it in:

# My first agent

## What it does
- One or two sentences. One task.

## How to run it
- What you need first (language version, keys or accounts)
- How to install it
- The command that starts it

## License
- The license name, and a LICENSE file in the repo

## Known limitations
- What it does not do yet
- What can go wrong, and what to check when it does

Step 3. Add a demo link (optional)

If your agent has a web page people can open, add it as the demo link. It must start with https://. No demo? That's fine: nothing is shown and your listing is not marked down for it.

Every 6 hours, Agraris checks demo links (Live check). If yours answers, the listing shows a small "Responding" label. After 3 failed checks in a row, it shows "Not responding".

"Responding" only means the demo URL answered. It says nothing about what the agent does. It is not an endorsement.

Step 4. Publish on Agraris

Open the publish form. Choose Agent or Tool, then fill in the name, a short description, a version, your repo link and a few category tags. The demo link and a contract address are optional. Building for a request on the Wanted board? Start from its "I built this" button instead (see Step 5).

After you submit, you get a status link.

  • It is your key. Anyone with the link can edit your listing. Save it somewhere private and don't share it.
  • Review comes first. New listings are checked by hand before they appear. The status link shows "Pending review" until then.
  • You can edit later. With the status link you can change the description, version, categories, demo link and contract address. The name and repo link stay as submitted.
  • Contract address (optional). If your agent has a contract with an owner() function, add its address. Once the listing is approved, open your status link with the owner wallet in your browser and sign a short message. Our server checks it against owner(), and the listing then shows "Contract owner signed a message". This only means the owner wallet signed a message. It is not an endorsement.

Step 5. After your listing appears

  • Keep it current. When you edit your listing through the status link, it shows up in the "Recently updated" panel on the home page for 30 days.
  • Answer a request. The Wanted board lists agents and tools people are asking for. When you build one that fits, press "I built this" on that request and publish through the form that opens. The link to the request is set when you submit; it can't be added to a listing afterwards.
